# LocalChef - Short-Term Improvement Objectives

This document tracks immediate and high-priority improvements for LocalChef. Focus is placed on reliability of SLM recipe generation, pantry data synchronization, and user experience.

---

## 1. Ingredient Deduction & "I Made This" Action (High Priority)
* **Goal**: Enable one-click pantry inventory update after cooking a generated recipe.
* **Details**:
  - Add an **"I Made This Recipe"** button at the bottom of generated recipes.
  - Parse the ingredients table from the SLM response.
  - Present an interactive confirmation modal/checklist allowing the user to adjust quantities used before deducting from `pantry.csv` (or removing depleted items).
  - Eliminates the need to manually navigate to `/pantry` and remove each item by hand.

---

## 2. Standalone Desktop Window / App Mode Emulation
* **Goal**: Run LocalChef in its own dedicated, native-feeling window instead of a standard browser tab.
* **Implementation Options**:
  - **Chromium / Edge App Mode (Zero new dependencies)**:
    - Update `run.bat` / launcher script to open Chrome or Edge with `--app=http://127.0.0.1:5000 --window-size=1200,800`.
    - Strips away browser address bars, navigation buttons, and bookmarks for an immediate native desktop app experience.
  - **`pywebview` Window Wrapper**:
    - Add lightweight `pywebview` integration in Python so starting the app directly opens a native GUI window with custom window controls and icon.

---

## 3. Recipe Quality & Pipeline Architecture
* **Pipeline / Two-Stage Generation**:
  - Split generation into a 2-step pipeline if single-step prompts struggle with complex pantries:
    - *Step 1 (Planner / Selector)*: Model selects viable ingredients and recipe concept.
    - *Step 2 (Chef / Executor)*: Model drafts the step-by-step instructions and yields based strictly on selected items.
* **Validation & Hallucination Guardrail**:
  - Add an automated post-generation checker that parses the recipe's ingredient list against the active `pantry.csv`.
  - Flag or visually highlight any ingredients in the UI that were not present in the pantry inventory.
* **JSON / Structured Output Integration**:
  - Test Ollama structured output mode (`format="json"` or Pydantic schema) for recipes to guarantee machine-parsable ingredients, equipment, instructions, and macro tables.

---

## 4. UI & Cooking Experience Enhancements
* **Visual Recipe Cards & Copy/Export**:
  - Format ingredients into clean tables or checklist cards.
  - Add a **Copy Recipe to Clipboard** and **Print / Save as Markdown/PDF** button.
  - Add interactive checkable instruction steps for following along while cooking.
* **Mobile / Tablet Kitchen Responsive View**:
  - Optimize the layout and touch targets for mobile and tablet screens positioned on kitchen counters.

---

## 5. Settings & Model Configuration UI
* **Model & Generation Settings**:
  - Add a Model Settings section to the `/customization` page allowing users to configure:
    - Target Ollama model name (e.g., `phi4-mini`, `qwen2.5:3b`, `llama3.2:3b`).
    - Generation temperature slider (default `0.2`).
    - Max response token cap.
    - Repetition penalty.
* **Dynamic Connection Check**:
  - Show live status of Ollama connection and available local models in the settings/cooking view.

---

## 6. User Documentation & Beginner Onboarding
* **Non-Developer Friendly README & Guide**:
  - Overhaul `README.md` to be welcoming to non-developer home cooks.
  - Include clear setup instructions, troubleshooting (e.g., starting Ollama), and visual screenshots/GIFs.
  - Document the `run.bat` one-click launcher clearly.

---
